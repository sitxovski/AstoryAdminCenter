# Astory Admin Center — prerequisites, build, run

Copyright (c) 2026 @sitxovski (Discord)

The panel is a Python web service that runs **on the game server** (HTTPS, port 17890). You deploy and control it **from your
development PC** over SSH. Nothing has to be compiled.

## 1. Install

| Where | What | How |
|---|---|---|
| PC + server | Python 3.11+ (3.13 recommended) | `install_prerequisites.bat` (winget `Python.Python.3.13`) or <https://www.python.org/downloads/> |
| PC + server | Python packages | `pip install -r requirements.txt` (the install script does it) |
| PC + server | Microsoft ODBC Driver 17 for SQL Server | winget `Microsoft.msodbcsql.17` or <https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server> |
| server | SQL Server 2019 Express, instance `SQLEXPRESS`, with the game databases | as in [Astory Server](https://github.com/sitxovski/AstoryServer) `Prerequisites\setup_server.ps1`; enable TCP/IP 1433. Another instance name: set `ASTORY_SQL_INSTANCE` on the PC before deploying (`MSSQLSERVER` = default instance) |
| PC (only for the self-test) | SQL Server Express **LocalDB** (`(localdb)\MSSQLLocalDB`) | SQL Server Express installer → *Download Media* → *LocalDB*, or <https://learn.microsoft.com/sql/database-engine/configure-windows/sql-server-express-localdb>; not needed with `--skip-selftest` |
| server | OpenSSH Server | `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0` (as Administrator) |
| PC | SSH client + key | built into Windows 10/11: `ssh-keygen -t ed25519 -f %USERPROFILE%\.ssh\astory_server` |
| optional | Tailscale VPN | winget `Tailscale.Tailscale` — gives the server a private address for the panel |
| optional | Discord bot application | <https://discord.com/developers/applications> → *New Application* → *Bot* → token (for announcements and the "Community" section) |
| optional | Telegram bot | Telegram → @BotFather → `/newbot` (owner notifications) |

Run on the PC: `install_prerequisites.bat`; on the server: `install_prerequisites.bat -Server`.

## 2. Configure

`_setup\configure.bat` in the repository root — server addresses, paths, the SSH key name, the server Python path, Discord IDs.
Run it in the AstoryClient and AstoryServer clones as well (same folder, side by side): the panel imports `AstoryClient\Tools\asda_paths.py`,
the bot and `tools\Admin` import `AstoryServer\Tools\Anticheat\db_connect.py`, and both still hold `@@ASTORY_…@@` placeholders until configured.
Secrets (database passwords, TOTP key, HTTPS certificate) are generated by the first deploy; see `_setup\SETUP.md`, section 3.
A Discord ID left as a placeholder does not stop the bot: it logs a warning and the feature that uses that channel stays off.

## 3. Deploy (= build)

```
python AstoryAdminCenter\deploy\deploy_admin_center.py               # offline self-test, then upload and install on the server
python AstoryAdminCenter\deploy\deploy_admin_center.py --skip-selftest
```

The deploy creates the `AsdaAdmin` database, SQL logins and rights, the Windows scheduled task `AsdaAdminCenter` (starts with
the server) and the firewall rule for TCP 17890, then checks that the panel answers.

**Self-test (step 1 of the deploy).** It needs SQL Server **LocalDB** on the PC (it creates and drops temporary databases there) and runs
for tens of minutes. Part of it compares the panel with files that exist only in the author's development environment and are not
published (`sql/adminc_99_rollback.sql`, `AstoryServer\Docs\SQL`, `AstoryClient\RawAssets`, the donor clients, changelogs, release store):
those checks are reported as `SKIP` with the missing file, and the summary line counts them separately. It was not run on a clean public
clone, so a check may still fail there for the same reason — in that case deploy with `--skip-selftest`.

**Client snapshots.** Without `AstoryClient\RawAssets` (it is not in the public AstoryClient) the deploy skips the client table and text
snapshots (`data/ref/shop_client.json`, `text_client.json`) with a warning; the "Game data" sections then show "client snapshot not built".

**SQL objects of server patches.** `adminc_04` / `adminc_09` grant the password columns of patch P52 (`us_pwsalt`, `us_pwhash`, …) only
when they exist; without them account creation and password change in the panel are unavailable. `adminc_32` (bot command `/register`)
needs them too.

## 4. Run

| Task | Command |
|---|---|
| status / start / stop / restart | `AstoryAdminCenter\bat\AdminCenter.bat` (menu) or `AdminCenter.bat status` |
| open the panel | `https://<server VPN address>:17890/`, or `AdminCenter.bat tunnel` → `https://localhost:17890/` |
| first owner account | `python AstoryAdminCenter\asda_admin.py user-add <login> --role owner`, then enable two-factor in "My account" |
| console commands | `python AstoryAdminCenter\asda_admin.py --help` (status, find, audit, changeset, stack, maint, events, …) |
| Discord / Telegram bot (on the PC) | `AstoryAdminCenter\DiscordBot`: `.env` with `DISCORD_TOKEN=…`, `GUILD_ID=…` (optional `DISCORD_PROXY=http://host:port` — by default no proxy; `HTTPS_PROXY` is used when `DISCORD_PROXY` is not set; empty or `none` = direct; Telegram: `TELEGRAM_PROXY`, then the same two); `telegram.env` with `TG_TOKEN=…`, `TG_CHAT=…`; the bot's SQL password is created by the deploy on the server (`REPORTS_PASSWORD` in `secrets\asda_admin.ini`) — copy it next to the bot into `reports.env` as one line `REPORTS_PASSWORD = …`; run `python oracle_bot.py` (watchdog: `ensure_oracle.ps1`) |
| self-test | `python AstoryAdminCenter\asda_admin.py selftest` (offline, needs LocalDB; see section 3), `selftest --live` (reads the live databases) |
| ban registry of the bot | copy `DiscordBot\BANNED_PLAYERS.example.md` to `DiscordBot\BANNED_PLAYERS.md` (git-ignored; an empty table = no bans) and deploy again — without it "send to all players" in «Подарки» is refused |
| PC scheduled tasks (releases / crash reports) | `deploy\schtasks\README.md` |
